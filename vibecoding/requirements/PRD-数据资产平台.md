# 1. 产品概述

## 1.1 产品定位

数据资产平台是数据中台的“价值展示层”和“度量中枢”，负责把分散的表、指标、标签、模型、API 等数据对象统一纳管，形成企业级数据资产目录，让数据资产"可搜索、可理解、可度量、可推荐、可运营"。

如果说数据治理平台是"管控底座"，数据开发平台是"生产车间"，那数据资产平台就是面向全公司的"数据超市"——让每个人都能找到自己需要的数据，并信任这些数据。

核心理念：
- **统一口径**：一个指标只有一个认证版本，告别"各说各话"
- **资产可视**：公司到底有多少数据、质量如何、谁在用、值多少钱，一目了然
- **智能推荐**：像电商推荐商品一样推荐相关数据资产
- **持续运营**：像运营产品一样运营数据资产，关注健康度、使用率、ROI

## 1.2 目标用户

### 核心用户
1. **数据分析师 / BI 工程师**
   - 日常找表、找指标、理解口径、确认数据来源
2. **业务运营人员**
   - 查看业务指标、标签体系、数据报告
3. **数据产品经理**
   - 管理指标定义、标签体系、数据产品
4. **数据治理人员**
   - 跟踪资产健康度、推动低质资产治理
5. **管理层**
   - 查看资产全景、投入产出比、中台建设成效

### 间接用户
- 数据开发工程师（查看指标定义和上下游关系）
- 安全合规人员（查看敏感资产分布）
- 外部数据消费者（通过服务市场间接使用）

## 1.3 核心价值

1. **找得到**：全局搜索 + 分类导航 + 智能推荐，3 步找到所需数据
2. **看得懂**：统一的指标定义、标签说明、资产描述，消除理解歧义
3. **信得过**：认证指标、质量评分、使用反馈，建立数据信任体系
4. **管得住**：指标全生命周期管理、标签计算管理、资产分级运营
5. **算得清**：资产价值评估、使用率统计、成本归属，让数据投入可量化

## 1.4 业务目标

### 短期目标（0~3个月）
- 完成核心指标体系梳理与平台化管理
- 建立数据资产目录（覆盖 80% 核心表和指标）
- 支持指标认证流程
- 上线标签中心基础能力

### 中期目标（3~6个月）
- 上线智能推荐与资产全景
- 建立资产健康度模型
- 支持资产价值评估与 ROI 分析

# 2. 功能模块详细设计

# 2.1 指标管理平台

## 2.1.1 功能描述

统一管理企业指标体系，支持从原子指标到派生指标到复合指标的层级管理，实现指标定义、计算口径、数据来源、负责人、认证状态、版本历史的全生命周期管理。

指标分层模型：
```
复合指标（GMV同比增长率 = (本月GMV - 上月GMV) / 上月GMV）
  ↑
派生指标（本月GMV = 原子指标 + 时间修饰 + 业务修饰）
  ↑
原子指标（GMV = SUM(支付金额) WHERE 支付状态=成功）
```

## 2.1.2 用户故事

### 用户故事 A：产品经理定义新指标
- 作为数据产品经理
- 我希望在指标管理平台中创建一个新指标，填写业务口径、计算公式、数据来源和负责人
- 这样所有人都能看到统一的定义，而不是每个人各自理解

### 用户故事 B：分析师查询指标口径
- 作为分析师
- 我希望搜索"活跃用户"时，能看到它的准确定义、计算逻辑、适用的业务域和认证状态
- 这样不同团队不会出现口径不一致的问题

### 用户故事 C：开发关联指标到表
- 作为数据开发
- 我希望在建 DWS 汇总表时关联到已定义的指标
- 这样指标的产出链路可追溯

### 用户故事 D：治理人员审核认证指标
- 作为治理人员
- 我希望对重要指标进行认证审核，确认口径正确、来源可靠后标记为"认证指标"
- 这样业务可以信任认证指标的权威性

## 2.1.3 界面原型描述

### 页面一：指标目录
- 顶部：搜索框（支持中文名、英文名、业务描述、计算公式搜索）
- 左侧：指标分类树（按业务域 → 主题域 → 业务过程 → 原子/派生/复合）
- 中间：指标列表
  - 指标名称、英文名、指标类型、所属主题域、认证状态、负责人、最近更新
- 右侧：快捷操作（我的指标、待审核、最近浏览、热门指标）

### 页面二：指标详情页
Tab 设计：
- **基本信息**：名称、英文名、业务口径、计算公式、指标类型、主题域、粒度、单位
- **数据来源**：关联表、字段、计算 SQL、调度任务
- **血缘关系**：指标上下游依赖可视化
- **使用情况**：引用该指标的报表/API/大屏列表、使用热度趋势
- **质量状态**：最近校验结果、历史质量趋势
- **版本历史**：口径变更记录、审批记录
- **讨论区**：用户反馈和问题讨论

### 页面三：指标创建/编辑
- 基本信息表单
- 计算逻辑配置（可视化公式编辑器或 SQL）
- 数据来源关联
- 审批流程配置

### 页面四：指标认证审核
- 待审核列表
- 审核详情：口径定义、数据来源、质量规则、使用情况
- 审核操作：通过、驳回、要求补充

## 2.1.4 核心规则和逻辑

1. 指标命名全局唯一（英文名），中文名可配置唯一性检查
2. 指标类型分为：原子指标、派生指标、复合指标
3. 派生指标必须关联修饰词（时间、地域、业务条件等）
4. 复合指标必须引用已有的原子或派生指标
5. 指标口径变更需走审批，审批通过后生成新版本
6. 认证指标需满足：口径明确 + 来源可靠 + 有质量规则 + 有负责人
7. 指标与表/字段/任务/报表/API 的关联关系自动或手动维护
8. 支持指标生命周期管理：草稿 → 待审核 → 已发布 → 已认证 → 已下线

## 2.1.5 对标来源
- 阿里 DataWorks：指标中心，原子→派生→复合分层体系
- 字节 DataLeap：指标管理与认证

# 2.2 标签中心

## 2.2.1 功能描述

统一管理实体标签体系（用户标签、商品标签、内容标签等），支持标签定义、标签类目管理、标签计算规则配置、标签质量监控和标签使用统计。

## 2.2.2 用户故事

### 用户故事 A：运营创建用户分群标签
- 作为运营人员
- 我希望创建一个"高价值用户"标签，定义规则为"近30天消费金额 TOP 10%"
- 这样可以在营销活动中精准触达目标用户

### 用户故事 B：分析师查询标签覆盖情况
- 作为分析师
- 我希望看到每个标签的覆盖人数、更新频率和数据来源
- 这样我可以用可信的标签做分析

### 用户故事 C：产品经理管理标签类目
- 作为数据产品经理
- 我希望按类目组织标签（人口属性、消费行为、偏好兴趣等），并设置类目负责人
- 这样标签体系不会混乱

## 2.2.3 界面原型描述

### 页面一：标签类目管理
- 左侧：类目树（支持拖拽排序）
- 右侧：类目详情（名称、负责人、标签数量、描述）

### 页面二：标签列表
- 筛选：类目、实体类型、标签类型（统计标签/规则标签/算法标签）、更新频率
- 列表：标签名称、类目、类型、覆盖量、更新频率、质量评分、负责人
- 行操作：查看详情、编辑、申请使用、下线

### 页面三：标签详情
- 基本信息：名称、类目、类型、实体类型、计算规则
- 覆盖统计：覆盖人数/物量、覆盖率趋势
- 数据来源：关联表和计算任务
- 使用情况：引用该标签的客群、营销活动、分析报告
- 质量监控：空值率、分布异常

### 页面四：标签规则配置
- 规则类型：SQL 规则 / 可视化规则 / 算法模型
- 调度配置：计算频率、依赖任务
- 输出配置：目标表、字段映射

## 2.2.4 核心规则和逻辑

1. 标签按实体类型隔离（用户、商品、内容等）
2. 标签类型：统计标签（聚合计算）、规则标签（条件判定）、算法标签（模型输出）
3. 标签命名在同类目下唯一
4. 标签下线需检查是否有活跃使用方
5. 标签质量监控包括：空值率、分布偏移、时效性
6. 支持标签组合生成客群（标签交集/并集/差集）

## 2.2.5 对标来源
- 字节 DataLeap：标签体系管理
- 网易数帆：用户画像与标签管理

# 2.3 数据目录

## 2.3.1 功能描述

面向全公司（含业务人员）的数据资产浏览和搜索入口，提供类似"购物网站"的数据浏览体验，让用户可以按分类浏览、搜索、查看详情、评价、收藏、申请使用。

## 2.3.2 用户故事

### 用户故事 A：业务人员浏览可用数据
- 作为业务人员
- 我希望像逛超市一样按主题域浏览数据资产
- 这样不用知道具体表名也能发现有用的数据

### 用户故事 B：用户评价数据质量
- 作为数据使用者
- 我希望对使用过的数据资产进行评分和评价
- 这样其他人可以参考我的使用体验

### 用户故事 C：管理员跟踪数据使用情况
- 作为数据管理员
- 我希望看到哪些数据被频繁使用、哪些无人问津
- 这样可以优化资源投入

## 2.3.3 界面原型描述

### 页面一：目录首页
- 顶部：搜索框 + 热门搜索词
- 分类导航：按主题域、按业务系统、按数据类型、按热门排行
- 推荐区：热门资产、最新上线、认证资产推荐
- 资产卡片：名称、描述摘要、认证状态、质量评分、热度、使用人数

### 页面二：分类浏览页
- 左侧：分类面包屑 + 子分类列表
- 中间：资产列表（列表/卡片视图切换）
- 右侧：筛选条件（质量、分层、更新时间、敏感等级）

### 页面三：资产详情页（复用治理平台资产详情，增加以下内容）
- 用户评价
- 相关推荐
- 使用申请入口
- 收藏/订阅

## 2.3.4 核心规则和逻辑

1. 目录数据来源于元数据中心，实时同步
2. 支持全文搜索 + 标签筛选 + 分类导航
3. 搜索排序综合：相关性、热度、质量评分、认证状态
4. 用户可对资产打分（1-5星）和文字评价
5. 支持收藏和订阅（变更通知）
6. 资产卡片信息需简明易懂，面向非技术人员

## 2.3.5 对标来源
- 阿里 DataWorks：数据地图（DataMap）
- 字节 DataLeap：全局搜索与智能推荐

# 2.4 智能推荐引擎

## 2.4.1 功能描述

基于用户行为、资产关联关系、使用场景，智能推荐相关的数据资产，降低数据发现成本。

## 2.4.2 用户故事

### 用户故事 A：发现关联表
- 作为分析师
- 当我查看"订单事实表"时
- 我希望平台推荐"常用关联维度表"和"基于此表的热门指标"
- 这样我不需要到处问人

### 用户故事 B：个性化推荐
- 作为数据开发
- 我希望在首页看到"与我最近工作相关的数据变更"和"同事在用的新资产"
- 这样我不会错过重要更新

## 2.4.3 界面原型描述

- 嵌入各页面的推荐模块
- 首页：个性化推荐、热门趋势、最近访问相关
- 资产详情页：关联推荐、相似资产、常用组合
- 搜索结果页："你可能还想找"

## 2.4.4 核心规则和逻辑

1. 推荐策略：协同过滤（相似用户）+ 内容关联（血缘/引用关系）+ 热度趋势
2. 新用户推荐热门资产，积累行为后个性化
3. 推荐结果可解释（推荐原因标注）
4. 支持用户反馈（有用/无用），优化推荐模型

## 2.4.5 对标来源
- 字节 DataLeap：智能推荐相关表和指标

# 2.5 资产全景与运营大盘

提供数据资产的全局视图，让管理层和运营人员了解公司数据资产总量、分布、质量、使用、成本、增长趋势等宏观信息。

## 2.5.2 用户故事

### 用户故事 A：管理层看数据资产总览
- 作为数据平台负责人
- 我希望在一个页面看到数据资产总量、认证率、使用率、健康度
- 这样我可以评估中台建设成效

### 用户故事 B：运营发现数据增长趋势
- 作为平台运营
- 我希望看到新增资产趋势、热门领域、冷门领域
- 这样可以引导治理和开发资源投入

## 2.5.3 界面原型描述

### 页面一：资产全景页
- 指标卡：总资产数、认证资产数、活跃资产率、平均健康度、总使用次数
- 图表：
  - 资产增长趋势（按月）
  - 按主题域分布（饼图）
  - 按分层分布（柱状图）
  - 质量分布（好/中/差）
  - 使用热度 Top10
  - 新上线资产排行

### 页面二：运营报表
- 周报/月报自动生成

## 2.5.4 核心规则和逻辑

1. 全景数据每日刷新
2. 支持按部门、主题域、分层等维度下钻
3. 运营报告支持自动推送（邮件/IM）
4. 核心指标对比上月/上周变化

# 2.6 主题域管理

## 2.6.1 功能描述

按照业务域划分数据资产边界，明确每个主题域的范围、负责人、包含的业务过程和核心指标，建立清晰的数据组织结构。

## 2.6.2 用户故事

### 用户故事 A：架构师划分主题域
- 作为数据架构师
- 我希望按业务域（交易、用户、商品、营销、物流等）划分数据资产
- 这样各域有明确的边界和负责人

### 用户故事 B：新人了解数据分布
- 作为新入职的数据分析师
- 我希望通过主题域导航快速了解公司有哪些数据
- 这样可以快速上手

## 2.6.3 界面原型描述

### 页面一：主题域地图
- 可视化展示各主题域及其关系
- 每个主题域卡片：名称、负责人、资产数量、核心指标数、健康度

### 页面二：主题域详情
- 基本信息：名称、描述、负责人、边界定义
- 关联资产：表、指标、标签、API 列表
- 治理状态：认领率、质量评分、标准符合度
- 业务过程：包含的业务过程和原子指标

## 2.6.4 核心规则和逻辑

1. 主题域划分需经架构委员会审批
2. 每个主题域必须指定域负责人
3. 资产归属主题域后，治理评分按域聚合
4. 跨域引用需标注并纳入治理评分
5. 支持主题域合并和拆分（需审批）

## 2.6.5 对标来源
- 网易数帆：主题域建模方法论

# 3. 非功能需求

## 3.1 性能要求

1. 全局搜索响应时间 < 2 秒
2. 指标详情页加载 < 3 秒
3. 资产全景大盘数据刷新 < 5 分钟
4. 推荐接口响应 < 500ms
5. 标签计算任务支持千万级实体

## 3.2 安全要求

1. 资产查看权限与治理平台统一
2. 指标和标签的创建/编辑需有权限控制
3. 认证指标变更需审批
4. 用户评价和反馈支持审核机制
5. 资产使用记录留存审计日志

## 3.3 可用性要求

1. 目录和搜索月可用性 >= 99.9%
2. 指标管理支持版本回滚
3. 标签计算任务失败自动告警
4. 评价和反馈支持举报和删除

# 4. MVP 范围定义

## 4.1 P0（第一版必须上线）

### 目标
建立"统一口径"和"可搜索的数据资产目录"。

### 范围
1. 指标管理（原子/派生/复合指标定义、认证流程、详情页）
2. 主题域管理（划分与资产归属）
3. 数据目录（搜索、浏览、详情、收藏）
4. 基础资产全景（资产总量、分布、趋势）
5. 标签中心（标签类目、标签定义、规则配置）

## 4.2 P1（第二阶段增强）

1. 智能推荐引擎
2. 指标血缘分析
3. 标签质量监控
4. 用户评价体系

# 5. 上线验收标准

1. 核心业务域指标梳理完成，覆盖 80% 常用指标
2. 指标认证流程跑通，核心指标认证率 >= 60%
3. 数据目录搜索准确率用户满意度 >= 80%
4. 主题域划分完成，核心域资产归属率 >= 90%
5. 资产全景数据准确，管理层可据此做决策

---

# 6. 风险与注意事项

1. **指标口径统一是最大难点**：需要业务深度参与，不能纯靠技术团队梳理
2. **标签体系容易膨胀**：需建立标签生命周期管理，定期清理无效标签
3. **推荐冷启动**：初期用户行为数据不足，推荐效果有限，需用热门排行过渡
4. **资产全景数据准确性**：依赖治理平台元数据质量
5. **业务参与度**：目录和指标管理需要业务方持续维护，需建立激励机制

# 7. 对外协同关系

- 与**数据治理平台**联动：获取元数据、标准、质量评分、认领信息、血缘关系
- 与**数据开发平台**联动：获取指标计算任务、标签计算任务、模型定义
- 与**数据服务平台**联动：追踪指标/标签/API 使用情况
- 与**数据应用平台**联动：追踪指标在报表/大屏中的使用情况
