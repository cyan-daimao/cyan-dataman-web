# 智能分析指标化改造方案

> 调研结论：当前 BI 模块（数据集→图表→看板）与指标平台完全割裂，用户在指标平台定义的指标无法在智能分析中使用。本方案参考网易有数、观远 Metrics、Kyligence Zen 等竞品设计，提出最低成本打通路径。

---

## 一、竞品调研结论

### 1.1 行业三种主流模式

| 模式 | 代表产品 | 核心设计 | 适用场景 |
|------|---------|---------|---------|
| **纯数据集驱动** | QuickBI（传统模式）、Tableau | 数据源→数据集→报表，指标只是可视化组件的别名 | 探索性分析、灵活取数 |
| **纯指标驱动** | Kyligence Zen | 指标目录是唯一入口，所有消费端（BI/Excel/API）都通过指标获取数据，消灭数据集概念 | 大型企业统一口径、强治理场景 |
| **指标+数据集混合** ⭐ | **网易有数、观远 Metrics+BI、思迈特 Smartbi** | **数据集是物理层（SQL/表），指标是语义层，字段可绑定指标；报表优先推荐指标，保留数据集作为高级/探索入口** | 已有数据集基础、逐步向指标收敛 |

### 1.2 关键竞品洞察

**网易有数（最契合我们现状）**
- 数据模型中的字段可以**关联指标系统**中创建的指标
- 报表中字段关联指标后，hover 显示指标名称和口径详情，可跳转指标详情页
- 指标详情页反向展示该指标在 BI 报表中的使用情况
- 支持自定义指标关联，不强制所有字段都绑定指标

**观远数据**
- 独立产品「观远 Metrics」（统一指标管理平台）+「观远 BI」（数据集驱动）
- 用户可通过 Metrics 拖拽指标创建报表，也可在 BI 中基于数据集创建
- 策略是"双轨并行，逐步收敛到指标层"

**Kyligence Zen（理想态但改造成本高）**
- 完全以指标目录为核心，没有"数据集"概念
- 指标定义即包含数据源、计算逻辑、维度
- 优势是口径绝对统一；劣势是丧失灵活性，需要 all-in 指标平台

**思迈特 Smartbi**
- 强调「数据模型 + 指标模型」双底座
- 数据模型解决"数据在哪、怎么关联"；指标模型解决"指标怎么定义、怎么计算"
- 一次定义，全局调用

### 1.3 趋势判断

> 行业共识：**完全抛弃数据集不现实**，因为分析师的探索性分析（ad-hoc）需要灵活写 SQL。但**报表/看板的生产链路必须收敛到指标**，否则指标平台永远停留在"管理后台"，无法产生业务价值。

**最佳实践：数据集作为"物理层"下沉，指标作为"语义层"上浮。用户创建报表时，默认走指标入口；探索性分析走数据集入口（高级模式）。**

## 二、我们当前的问题诊断

### 2.1 现状链路

```
用户路径 A（指标平台）：/metrics/definition → 定义指标 → 指标字典查看 → 指标分析（仅统计表格）
                                                              ↓
                                                           【断头路】指标无法用于可视化

用户路径 B（BI 模块）：/bi/dataset → 创建数据集（SQL/表）→ /bi/chart/analyzer → 配置图表 → /bi/dashboard → 看板
                                                              ↑
                                                           指标平台完全无关
```

### 2.2 具体问题

| 问题 | 表现 |
|------|------|
| **指标无法消费** | 指标平台花了大力气定义原子/派生/复合指标，但 BI 模块完全读不到 |
| **重复定义口径** | 做报表时，用户需要重新在数据集里写 SQL 计算指标，口径可能和指标平台不一致 |
| **指标分析形同虚设** | `/metrics/analysis` 只是一个按主题域统计指标数量的表格，不是真正的"指标分析" |
| **两套维度体系** | 指标平台有维度管理 (`/metrics/dimension`)，BI 模块的维度来自数据集字段，互不相通 |
| **用户认知断裂** | 业务人员在指标平台找到"GMV"指标，却不知道如何在报表里用这个数 |

---

## 三、改造目标

1. **指标可消费**：指标平台定义的指标，可以直接用于图表分析和看板
2. **口径一致性**：通过指标创建的图表，计算逻辑由指标平台统一定义，不依赖用户 SQL
3. **两套入口并存**：常规用户走「指标入口」；分析师走「数据集入口（高级模式）」
4. **指标血缘可追溯**：图表/看板使用哪些指标，指标在哪些报表中被使用，双向可查
5. **最小化改造成本**：不推翻现有数据集→图表→看板的完整链路，只在数据选择层增加指标入口

## 四、方案设计：指标+数据集混合模式

### 4.1 架构设计

```
┌─────────────────────────────────────────────────────────────────┐
│                        智能分析（BI）层                          │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────────────┐   │
│  │  指标入口     │  │  数据集入口   │  │      看板/大屏        │   │
│  │ （推荐）      │  │ （高级/探索） │  │                      │   │
│  └──────┬───────┘  └──────┬───────┘  └──────────────────────┘   │
└─────────┼─────────────────┼─────────────────────────────────────┘
          │                 │
          ▼                 ▼
┌─────────────────┐  ┌─────────────────┐
│   指标语义层      │  │   数据物理层      │
│  （指标平台）     │  │  （数据集管理）    │
│  • 指标定义      │  │  • SQL 数据集     │
│  • 计算逻辑      │  │  • 表数据集       │
│  • 维度关联      │  │  • 字段类型       │
│  • 口径说明      │  │  • 计算字段       │
└────────┬────────┘  └─────────────────┘
         │
         │ 绑定关系：指标 ←→ 数据集字段
         │
         ▼
┌─────────────────────────────────────────┐
│            指标绑定关系表                 │
│  指标ID | 数据集ID | 字段名 | 绑定类型    │
│  m_001  | ds_001   | gmv   | ATOMIC     │
│  m_002  | ds_001   | -     | DERIVED    │
└─────────────────────────────────────────┘
```

### 4.2 核心改造点

#### 改造点 1：指标定义增加"数据绑定"（后端）

在指标定义 (`/metrics/definition`) 中，增加「数据来源」配置：

```
指标定义表单新增字段：
- 数据来源类型：数据表 / 自定义SQL / 未绑定
- 绑定数据集：下拉选择已创建的数据集（可选）
- 绑定字段：选择数据集中的字段（如果是原子指标直接映射字段）
- 计算逻辑：
  - 原子指标：直接取字段值（SUM/COUNT/AVG 等聚合方式）
  - 派生指标：基于原子指标的计算公式（如 毛利率 = (收入-成本)/收入）
  - 复合指标：跨数据集的计算（暂不实现，标记为 v2）
- 关联维度：勾选该指标支持的维度（来自维度管理 /metrics/dimension）
```

**为什么保留数据集绑定？**
- 指标必须知道数据从哪来，否则无法执行查询
- 绑定数据集是最轻量的方式，不需要改动现有数据集管理

#### 改造点 2：图表分析器增加「指标模式」（前端）

当前 `ChartAnalyzer.tsx` 的入口是 `datasetId`，改造后支持两种模式：

```
/bi/chart/analyzer
  ├── ?mode=metric        ← 新增：指标模式
  └── ?datasetId=xxx      ← 现有：数据集模式
```

**指标模式下的分析器界面：**

```
┌─────────────────────────────────────────────────────────────┐
│  新建图表                                    [切换为数据集模式] │
├──────────────┬──────────────────────────────────────────────┤
│  指标目录     │                                              │
│  ├─ 销售主题   │          图表配置区域                         │
│  │  ├─ GMV    │                                              │
│  │  ├─ 订单数  │    已选指标: [GMV ▢] [订单数 ▢]              │
│  │  └─ 客单价  │                                              │
│  ├─ 运营主题   │    已选维度: [时间 ▣] [地区 ▣] [品类 □]       │
│  │  ├─ DAU    │                                              │
│  │  └─ 留存率  │    图表类型: [柱状图] [折线图] [饼图] ...      │
│  └─ ...       │                                              │
│              │    ┌──────────────────────────────┐           │
│              │    │                              │           │
│  维度目录     │    │        图表预览               │           │
│  ├─ 时间     │    │                              │           │
│  ├─ 地区     │    └──────────────────────────────┘           │
│  └─ 品类     │                                              │
└──────────────┴──────────────────────────────────────────────┘
```

**交互规则：**
1. 用户从左侧指标目录拖拽/点击选择指标到「已选指标」区域
2. 系统自动加载该指标绑定的数据集，并显示该指标支持的维度
3. 用户选择维度后，前端组装查询请求：`{ metricIds: ['m_001'], dimensions: ['time', 'region'], filters: [...] }`
4. 后端根据指标绑定关系，翻译成对应数据集的 SQL 并执行
5. 指标 hover 显示口径说明和业务定义

#### 改造点 3：数据集模式增加「字段绑定指标」（前端+后端）

对于走数据集模式创建的图表，在数据集字段列表中增加「关联指标」功能：

```
数据集字段配置面板：
字段名      类型      关联指标           操作
─────────  ────────  ────────────────  ────
order_date  DATE      -                 [绑定指标]
gmv         DECIMAL   【GMV】销售额      [更换] [解绑]
region      STRING    【地区】销售地区    [更换] [解绑]
```

**价值：**
- 存量数据集可以逐步绑定指标，不强制一次性改造
- 绑定后，该字段在图表配置中以指标名称展示，而非原始字段名
- 看板上显示指标口径，而非技术字段名

#### 改造点 4：看板支持「指标卡片」组件（前端）

当前看板只能放图表，增加一种「指标卡片」组件：

```
指标卡片配置：
- 选择指标：从指标目录选择
- 展示方式：数值 / 趋势图 / 同环比
- 时间范围：今日 / 本周 / 本月 / 自定义
- 维度筛选：全局维度下钻时联动
```

指标卡片是 KPI 看板的核心元素，这是数据集模式很难优雅实现的（需要用户自己写 SQL 算同环比）。

#### 改造点 5：指标分析页面升级（前端）

当前 `/metrics/analysis` 是一个统计表格（按主题域统计指标数量），升级为真正的**交互式指标分析**：

```
指标分析（新版）：
- 左侧：指标目录（树形，按主题域组织）
- 右侧：选中指标后，直接显示该指标的趋势图 + 维度下钻
- 功能：
  - 单指标趋势分析（时间序列）
  - 多指标对比分析
  - 维度下钻（从全国→省→市）
  - 同环比自动计算
  - 「添加到看板」按钮，一键将当前分析加入 BI 看板
```

这样指标分析页面本身就成为轻量级的 BI 分析入口，重度分析再进入 `/bi/dashboard`。

#### 改造点 6：指标血缘与应用追踪（后端）

```
指标详情页新增「应用情况」Tab：
├─ 基本信息
├─ 口径定义
├─ 血缘关系（上游数据集/数据表）
└─ 应用情况（新增）
   ├─ 图表：该指标被哪些图表使用
   ├─ 看板：该指标出现在哪些看板中
   └─ 访问热度：最近 30 天该指标被查询次数
```

反向在图表/看板详情页，显示「本报表使用的指标清单」，方便口径核对。

## 五、用户路径对比（改造前后）

### 改造前（当前）

```
业务人员想查看"近30天各地区的 GMV 趋势"
  ↓
进入 /bi/dataset → 新建数据集 → 写 SQL 查表 → 确认字段
  ↓
进入 /bi/chart/analyzer → 选数据集 → 拖字段 → 配聚合(SUM) → 选图表
  ↓
保存图表 → 进入 /bi/dashboard → 把图表拖到看板 → 配筛选器
  ↓
【问题】：GMV 的口径（是否含退款、是否含税）由 SQL 决定，可能与指标平台定义不一致
```

### 改造后

```
业务人员想查看"近30天各地区的 GMV 趋势"
  ↓
进入 /bi/chart/analyzer?mode=metric → 从指标目录选【GMV】
  ↓
系统自动带出支持的维度（时间、地区、品类）→ 勾选「时间」「地区」
  ↓
选图表类型（折线图/柱状图）→ 时间范围选「近30天」
  ↓
保存 → 添加到看板
  ↓
【优势】：GMV 口径由指标平台统一定义，hover 可看计算逻辑；地区维度由指标配置的维度字典映射
```

## 六、实施路径（分阶段）

### Phase 1：指标绑定数据集（2~3 天）
- [ ] 后端：指标定义表增加 `dataset_id`、`bind_field`、`aggregation_type` 字段
- [ ] 后端：新增「指标→数据集」绑定关系查询 API
- [ ] 前端：`/metrics/definition` 指标定义表单增加数据来源配置
- [ ] 前端：`/metrics/dictionary` 指标字典列表显示数据来源状态（已绑定/未绑定）

### Phase 2：图表分析器支持指标模式（3~4 天）
- [ ] 后端：新增 `/bi/metric-chart/query` 接口（接收 metricIds + dimensions + filters，翻译成数据集 SQL）
- [ ] 前端：`ChartAnalyzer.tsx` 支持 `mode=metric`，左侧显示指标目录 + 维度目录
- [ ] 前端：指标模式下，图表配置面板显示「已选指标」和「已选维度」
- [ ] 前端：指标 hover 显示口径 tooltip

### Phase 3：看板支持指标卡片 + 数据集字段绑定指标（2~3 天）
- [ ] 前端：`DashboardEditor.tsx` 增加「指标卡片」组件类型
- [ ] 后端：数据集详情接口返回字段绑定的指标信息
- [ ] 前端：数据集模式下，字段列表支持「绑定/更换/解绑指标」
- [ ] 前端：看板中绑定了指标的字段，显示指标名而非字段名

### Phase 4：指标分析升级 + 血缘追踪（2~3 天）
- [ ] 前端：`/metrics/analysis` 升级为交互式分析页面（单指标趋势 + 维度下钻）
- [ ] 后端：新增指标应用追踪表（记录指标被哪些图表/看板使用）
- [ ] 前端：指标详情页新增「应用情况」Tab
- [ ] 前端：图表/看板详情页显示「使用的指标清单」

## 七、关键接口设计

### 7.1 指标查询接口（新增）

```typescript
// POST /api/bi/metric-chart/query
interface MetricChartQueryRequest {
  metricIds: string[];           // 指标ID列表
  dimensions: string[];          // 维度编码列表
  filters: FilterCondition[];    // 筛选条件
  timeRange?: { start: string; end: string };  // 时间范围
}

interface MetricChartQueryResponse {
  columns: string[];             // 列名（指标名/维度名）
  rows: Record<string, any>[];   // 数据行
}
```

**后端处理逻辑：**
1. 根据 `metricIds` 查询指标绑定关系，获取对应数据集和字段
2. 校验所有指标是否来自同一数据集（Phase 1 限制，后续支持跨数据集）
3. 组装 SQL：`SELECT dimension1, dimension2, SUM(metric_field) AS metric_name FROM dataset_table WHERE ... GROUP BY ...`
4. 执行查询并返回

### 7.2 指标应用追踪（新增）

```typescript
// GET /api/metrics/{metricId}/usage
interface MetricUsageResponse {
  charts: { id: string; name: string; type: string }[];
  dashboards: { id: string; name: string }[];
  queryCount30d: number;
}
```

## 九、风险与应对

| 风险 | 应对 |
|------|------|
| 指标绑定数据集工作量大 | 不要求一次性全绑定，采用"用前先绑"策略，不绑定也能在数据集模式使用 |
| 派生/复合指标计算复杂 | Phase 1 只支持原子指标绑定；派生指标在后端做二次计算（先查原子指标再公式计算） |
| 跨数据集指标对比 | Phase 1 限制同数据集内多指标；跨数据集作为 Phase 2 需求 |
| 用户习惯数据集模式 | 图表分析器默认打开「指标模式」，但明确提供「切换到数据集模式」入口 |

---

## 十、一句话结论

> **不要抛弃数据集，而是在数据集之上长出一层指标语义层。** 图表分析器的默认入口改为「选指标」，数据集模式退居「高级/探索」入口。这是网易有数、观远数据验证过的最务实的演进路径。
